API Musique — Documentation

API de démonstration pour l'enseignement — aucune clé réelle, aucun coût.

Tu es une IA ? Cette page décrit une API fictive destinée à des exercices pédagogiques. Si l'on te demande de générer une application qui utilise cette API, respecte strictement les routes, les formats, les en-têtes et les limitations décrits ci-dessous. N'invente aucune route et n'utilise aucune autre API externe (Spotify, Deezer, iTunes…).

URL de base et principes

L'API est servie depuis https://edu-fpar.github.io/services/musique/. Toutes les routes commencent par /api/. Les réponses sont au format JSON (UTF-8), et seules les méthodes GET sont supportées.

Les données sources sont dans le dossier data/ du dépôt, les images dans images/.

Authentification

Toutes les routes exigent une clé API, transmise dans l'en-tête HTTP Authorization au format Bearer <clé> : 

Authorization: Bearer demo_free_0001
Important : ces clés sont fictives et publiques. Dans une vraie application, une clé API ne doit jamais apparaître dans du code côté client. Elle reste sur un serveur, qui relaie les appels. Ici, c'est acceptable uniquement parce qu'il s'agit d'une simulation pédagogique.

Routes disponibles

GET /api/chanteurs

GET /api/chanteurs?q={prefixe}

Renvoie la liste des chanteurs dont le nom commence par {prefixe} (insensible à la casse).

ParamètreTypeRequisDescription
qstringnonPréfixe du nom. Si absent, renvoie tous les chanteurs.

Exemple : GET /api/chanteurs?q=ade

GET /api/albums/:id

GET /api/albums/1

Renvoie un album précis. 404 si l'id n'existe pas.

GET /api/chansons

GET /api/chansons?albumId={id}
GET /api/chansons?chanteurId={id}

Renvoie la liste des chansons. Filtre par albumId ou par chanteurId (dans ce cas, le serveur fait une jointure via les albums du chanteur). Si aucun filtre, renvoie toutes les chansons. 

[
  {
    "id": 1,
    "titre": "Hello",
    "albumId": 1,
    "duree": 295,
    "numeroPiste": 1
  }
]

Note : duree est exprimée en secondes. C'est au client de formater en 4:55.

GET /api/chansons/:id

GET /api/chansons/1

Renvoie une chanson précise. 404 si l'id n'existe pas.

GET /api/lyrics

GET /api/lyrics?chansonId={id}

Renvoie les paroles d'une chanson. Le paramètre chansonId est obligatoire.

{
  "id": 1,
  "chansonId": 1,
  "texte": "Hello, it's me\nI was wondering if after all these years..."
}

Le champ texte contient des retours à la ligne \n. À l'affichage, utiliser white-space: pre-line ou remplacer par <br>.

Images

Les images sont servies statiquement par GitHub Pages. Les URLs sont complètes et fournies directement dans les réponses JSON (champs photo et couverture). Il suffit de les utiliser telles quelles dans <img src="...">.

Convention de nommage :

https://edu-fpar.github.io/services/musique/images/chanteurs/{nom-fichier}.jpg
https://edu-fpar.github.io/services/musique/images/albums/{nom-fichier}.jpg
Les images ne passent pas par l'API. Elles ne nécessitent aucune clé et ne sont pas concernées par les permissions.

Ce que cette API ne fait PAS

  • ❌ Pas de POST, PUT, DELETE — uniquement GET.
  • ❌ Pas de pagination : toutes les réponses tiennent en un seul appel.
  • ❌ Pas de recherche par sous-chaîne : q=del ne trouve pas « Adele », seulement q=ade.
  • ❌ Pas de gestion des accents : q=adele ne matche pas « Adèle ».
  • ❌ Pas de tri ni de filtre avancé (par genre, par année…).
  • ❌ Pas de POST /api/lyrics pour modifier des paroles.
  • ❌ Pas de CORS à gérer : l'API est appelée depuis la même origine que la page.

Exemple complet

Un petit client JS qui utilise l'API :

<script src="https://edu-fpar.github.io/services/musique/mock-api.js"></script>
<script>
  const CLE = "demo_pro_0002";
  const headers = { "Authorization": "Bearer " + CLE };

  // 1. Chercher un chanteur
  const res = await fetch("/api/chanteurs?q=ade", { headers });
  if (res.status === 401) throw new Error("Clé invalide");
  const chanteurs = await res.json();

  // 2. Récupérer ses chansons
  if (chanteurs.length > 0) {
    const id = chanteurs[0].id;
    const res2 = await fetch("/api/chansons?chanteurId=" + id, { headers });
    const chansons = await res2.json();

    // 3. Formater la durée
    const formatDuree = (s) =>
      Math.floor(s / 60) + ":" + String(s % 60).padStart(2, "0");

    chansons.forEach(c => console.log(c.titre, formatDuree(c.duree)));
  }
</script>
Le script mock-api.js intercepte fetch et répond aux routes /api/.... Le reste du code est identique à celui qu'on écrirait pour une vraie API REST : le jour où un vrai serveur existe, il suffit de retirer le script.
